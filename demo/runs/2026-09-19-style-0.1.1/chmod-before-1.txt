`chmod 755` sets Unix file permissions to `rwxr-xr-x`:

| Who | Digit | Bits | Meaning |
|---|---|---|---|
| Owner | 7 | `rwx` | read, write, execute |
| Group | 5 | `r-x` | read, execute (no write) |
| Others | 5 | `r-x` | read, execute (no write) |

Each digit is the sum of read (4), write (2), and execute (1). So 7 = 4+2+1, 5 = 4+0+1.

**What it means in practice:**
- **Files** — the owner can edit and run it; everyone else can read and run it. This is the standard mode for executables and scripts you want others to be able to invoke.
- **Directories** — `x` means "can traverse into," and `r` means "can list contents." So the owner can create/delete entries; everyone else can `cd` in and `ls`, but not add or remove files. This is the standard mode for directories like `/usr/bin` or a web root.

Common neighbors: `644` (`rw-r--r--`) for ordinary non-executable files, `700` for private directories, `600` for private files like SSH keys.

Worth noting since you're on Windows: `chmod` is a no-op concept for NTFS paths — Windows uses ACLs instead (`icacls`). It does apply inside WSL, Git Bash's emulation layer (partially), and on any remote Linux box you're deploying to.
