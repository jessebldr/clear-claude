`chmod 755` sets a file's permission bits to `rwxr-xr-x`:

| Who | Digit | Bits | Meaning |
|---|---|---|---|
| Owner | 7 | `rwx` | read, write, execute |
| Group | 5 | `r-x` | read, execute |
| Others | 5 | `r-x` | read, execute |

Each digit is the sum of read (4), write (2), and execute (1). So 7 = 4+2+1, and 5 = 4+1.

**In practice:** the owner can do anything to the file; everyone else can read and run it but not modify it. This is the standard mode for executables and scripts (`/usr/local/bin/foo`) and for directories you want others to browse — on a directory, `x` means "can traverse into it" and `r` means "can list its contents."

Related common modes:
- `644` (`rw-r--r--`) — normal data files, no execute
- `700` (`rwx------`) — private scripts, owner only
- `600` (`rw-------`) — private data, e.g. SSH private keys

One note since you're on Windows: `chmod` doesn't apply to NTFS paths natively. Inside Git Bash it mostly no-ops, though git itself tracks a single executable bit (`core.fileMode`), which is why you sometimes see `100644` → `100755` mode changes in diffs.
